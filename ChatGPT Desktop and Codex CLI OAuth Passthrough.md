# Configuring OAuth Passthrough for ChatGPT Desktop (Work and Codex), and Codex CLI

OAuth Passthrough lets you route **ChatGPT Desktop (Work and Codex)** and the **Codex CLI** through the Airia AI Gateway while you keep signing in with your **own ChatGPT account** — no Airia-managed API key required for inference.

**What this means for you:**

- Requests run on **your ChatGPT plan** (Plus, Pro, Team, Enterprise, or Go). Your Airia balance is **never debited** for these requests.
- Every request is attributed to **you** — your ChatGPT email and plan are read from your sign-in and shown on the request in Airia — not to a shared key.
- Your organization's Airia controls still apply: model allow-list, budget rules, guardrails/constraints, and rate limits.
- Setup is the same shape as the standard Codex integration: one block added to `config.toml`, no separate `.env` file or Airia API key to store on your machine.

**Inference path:** ChatGPT Desktop (Work / Codex) or Codex CLI → your ChatGPT sign-in → `config.toml` → Airia Gateway → `POST /openai/v1/responses` → OpenAI (on your ChatGPT plan)

## 1. Prerequisites & Routing Model

| Prerequisite | Detail |
|---|---|
| ChatGPT Desktop | Installed, with the Codex workspace opened and initialized at least once. |
| Codex CLI | Installed and run at least once, so the `.codex` folder exists. |
| ChatGPT sign-in | Signed in to Codex with your own ChatGPT account (Plus, Pro, Team, Enterprise, or Go). You keep using this sign-in — nothing about how you log in changes. |
| Airia OAuth Passthrough key | An `x-airia-key` value from your Airia workspace, generated for a gateway configuration that has **OAuth Passthrough enabled for OpenAI**. Ask your Airia admin if you don't have one — see below. |
| Gateway endpoint | `https://prodaus.gateway.airia.ai/openai/v1` |
| Model ID | A model that is both on your Airia gateway's allow-list **and** offered by your ChatGPT plan. This guide uses `gpt-5.6-sol` as the example. |

**OAuth Passthrough must be turned on for your workspace.** It's an opt-in setting on the OpenAI provider configuration in Airia (off by default). Ask your Airia technical representative to enable it.

**How it works:** ChatGPT Desktop (Work and Codex) and the Codex CLI all read the same `config.toml`. OAuth Passthrough does **not** store an Airia API key as your inference credential — Codex keeps sending your normal ChatGPT sign-in token, and the gateway simply forwards it to OpenAI instead of replacing it. The `x-airia-key` in `config.toml` only tells the gateway which workspace configuration to use; it does not grant model access by itself.

**What's covered:** the Codex CLI, the Codex IDE extension, and — in the unified ChatGPT desktop app — the **Codex** and **Work** surfaces. The desktop app's separate **Chat** surface is not covered: it has no configuration file and always talks to ChatGPT directly, so it is unaffected by this setup either way.

## 2. Locate config.toml

| Platform | Location |
|---|---|
| macOS | `~/.codex/config.toml` — open Finder, press `⌘ Shift + G`, enter `~/.codex`, press **Go**. Press `⌘ Shift + .` to show hidden items if needed. |
| Windows | `%USERPROFILE%\.codex\config.toml` (typically `C:\Users\<you>\.codex\config.toml`) — open File Explorer, enter `%USERPROFILE%\.codex` in the address bar. Enable **View → Show → Hidden items** if needed. |

Open `config.toml` in a plain-text editor (TextEdit, Notepad, VS Code, etc.).

## 3. Add the Airia OAuth Passthrough provider block

Your `config.toml` may already contain settings written by ChatGPT Desktop or the Codex CLI (marketplace, plugin, MCP, desktop, project, and computer-use sections). **Leave all of those in place.**

**Add the following block at the very top of `config.toml`**, above any existing settings, then save:

```toml
model_provider = "airia"

# --- Airia Gateway (begin) ---
[model_providers.airia]
name = "Airia AI Gateway"
base_url = "https://prodaus.gateway.airia.ai/openai/v1"
wire_api = "responses"
requires_openai_auth = true
http_headers = { "x-airia-key" = "YOUR_AIRIA_OAUTH_PASSTHROUGH_KEY" }
# --- Airia Gateway (end) ---

# ── Existing settings generated by ChatGPT Desktop / Codex CLI ──
# (marketplace, plugin, MCP, desktop, project, computer-use, etc.)
# remain unchanged below this point.
```

Replace `YOUR_AIRIA_OAUTH_PASSTHROUGH_KEY` with the value from your Airia workspace's Integrate dialog for this OpenAI configuration.

Notes on the fields:

- `requires_openai_auth = true` tells Codex to keep sending your ChatGPT sign-in token with each request — this is what makes the request run on your ChatGPT plan instead of an Airia-managed key.
- There is **no `env_key`** and **no `.env` file** to create for this setup. The `x-airia-key` above identifies your workspace configuration to the gateway; your ChatGPT sign-in remains the credential that actually authorizes inference.
- If you want to pin a specific model, add `model = "gpt-5.6-sol"` above `model_provider`. Only pin a model that your ChatGPT plan actually offers — a pinned model your plan doesn't have access to will fail every turn (see Troubleshooting).

**Optional:** if your Airia admin generated a full **Automate Codex Setup** script from the Integrate dialog, you can run that instead of editing `config.toml` by hand — it merges the same block in safely and is safe to re-run.

## 4. Restart ChatGPT Desktop or Codex CLI

Save `config.toml`, then reload whichever surface you use:

- **ChatGPT Desktop:** Fully quit the app (macOS: `⌘Q`; Windows: quit from the system tray or end the process in Task Manager) — closing the window is not enough. Reopen, switch to the **Codex** (or **Work**) workspace, and start a new session.
- **Codex CLI:** Exit the running `codex` process, then start a new session so `config.toml` is reloaded.

You do **not** need to sign out of ChatGPT. Stay signed in with your existing account.

## 5. Validate the Connection

### Send a test prompt

1. Start a new session in the ChatGPT Desktop **Codex**/**Work** workspace, or in the Codex CLI.
2. Send any ordinary prompt and confirm you get a response.
3. Note the approximate send time so the request is easy to find in Airia.

### Confirm in Airia

In Airia, go to **Audit → Gateway Monitoring** and find the request generated by your prompt. Confirm:

- **Request appears** — a recent log entry matches your prompt.
- **Correct route** — the request went through the configured OpenAI gateway endpoint.
- **Verified identity** — opening the request's call details shows your ChatGPT email and plan tier as the attributed user, rather than a shared key.
- **No balance debit** — the request does not draw down your Airia balance; usage is still logged for reporting.
- **Successful result** — the request completed without an authentication or gateway error.

## 6. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `403 OAuth passthrough is not enabled for this provider on this gateway.` | OAuth Passthrough hasn't been turned on for the OpenAI provider in your Airia workspace. | Ask your Airia admin to enable OAuth Passthrough on the OpenAI provider configuration you're using. |
| `401 This gateway configuration requires user impersonation. Include your Authorization: Bearer token...` | Codex isn't sending your ChatGPT sign-in token — usually means you aren't signed in, or `requires_openai_auth` is missing/`false` in `config.toml`. | Sign in to Codex with your ChatGPT account, and confirm `requires_openai_auth = true` is in the `[model_providers.airia]` block. |
| `401` / `Unauthorized` on the `x-airia-key` itself | The Airia key is invalid, expired, or copied incorrectly. | Re-copy the key from the Integrate dialog for the correct OpenAI OAuth Passthrough configuration. |
| `400` — "The '\<model\>' model is not supported when using Codex with a ChatGPT account." | You pinned a `model` in `config.toml` that your ChatGPT plan doesn't offer. | Remove the `model` pin, or set it to a model your plan supports. |
| `404` on inference | The provider base URL or path is incorrect. | Confirm `base_url` is exactly `https://prodaus.gateway.airia.ai/openai/v1` and `wire_api = "responses"`. |
| Changes appear ignored | The app or CLI still holds the old session/config. | Fully quit and reopen ChatGPT Desktop, or exit and restart the Codex CLI. |
| Nothing happens when I use the **Chat** surface | The Chat surface of the ChatGPT app doesn't read `config.toml` and never routes through Airia. | Expected — use the **Codex** or **Work** surface, or the Codex CLI, for requests you want to see in Airia. |

## 7. Security Notes & Rollback

**Security**

- Your ChatGPT sign-in remains the credential that authorizes inference — nothing changes about how you log in or how OpenAI bills your plan.
- The `x-airia-key` in `config.toml` identifies your Airia workspace configuration; treat it the same way you'd treat any other workspace credential, and don't share it outside your organization.
- This change affects Codex inference routing for ChatGPT Desktop (Codex and Work surfaces) and the Codex CLI only — standard ChatGPT Chat conversations are unaffected either way.
- Your organization's Airia model allow-list, budget rules, guardrails, and rate limits continue to apply to passthrough requests, exactly as they do for Airia-managed-key requests.

**Rollback**

To stop routing through Airia and return to default Codex behavior, remove or comment out:

```toml
model_provider = "airia"
```

You may keep or remove the `[model_providers.airia]` block. Fully restart ChatGPT Desktop or the Codex CLI after the change.
